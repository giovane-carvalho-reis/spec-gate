# ADR-003 — Mermaid como formato unico de diagrama

## Status
Aceita.

## Contexto
A visão listava Mermaid, PlantUML, Structurizr DSL e DBML. Os artefatos precisam ser
legíveis por agente de IA, renderizáveis sem ferramenta externa, e versionáveis como texto.

## Decisão
Mermaid, único, para todos os diagramas: contexto, contêiner, classe, ER, fluxo e
sequência. O diagrama vive dentro do documento que ele ilustra, nunca em pasta paralela.

## Alternativas consideradas
| Alternativa | Por que não |
|---|---|
| PlantUML | Não renderiza no GitHub sem serviço externo; exige Java ou servidor |
| Structurizr DSL | Mais correto para C4, mas exige ferramenta para visualizar |
| DBML para o banco | Mais expressivo em schema, mas não renderiza no GitHub e seria um segundo formato |
| Mermaid + DBML, DBML como fonte | Duas representações do mesmo schema divergem |
| Pasta `diagrams/` separada | O documento inteiro reclama de artefato inconsistente; pasta paralela é como isso acontece |

## Consequências
**Ganhos:** renderiza no GitHub direto. Texto no diff. Uma sintaxe só para aprender. O
agente lê o diagrama como lê o resto.

**Custos e novas restrições:** Mermaid é menos expressivo que DBML para schema — tipo e
constraint vão para a tabela ao lado do ER, não para o diagrama. Não há geração de DDL a
partir do modelo.

**O que fica mais difícil depois desta decisão:** diagrama de arquitetura muito grande.
Mermaid fica ilegível antes de PlantUML ficar.
