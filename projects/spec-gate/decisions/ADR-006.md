# ADR-006 — Gate como exit code de script local

## Status
Aceita.

## Contexto
A verificação precisa ser rodada a toda hora para valer algo. Se custar crédito ou
segundos, deixa de ser rodada — e a especificação apodrece sem ninguém notar.

## Decisão
Os 10 gates são um script Python local com exit code: 0 pronto, 1 bloqueado, 2 erro de
uso. Nenhuma chamada de LLM. Cada pendência cita o gate e o arquivo. Autoteste próprio
(`test_validate.py`).

## Alternativas consideradas
| Alternativa | Por que não |
|---|---|
| Checklist em prompt, revisado por IA | Custa crédito, é não determinístico, e a mesma pasta pode passar hoje e falhar amanhã |
| Hook de git | Acopla a verificação ao commit; o autor quer validar antes de commitar |
| Validação dentro de uma skill | Skill não tem exit code, e a IA poderia "interpretar" o gate |
| CI no GitHub | Projeto individual e local; feedback chegaria tarde demais |

## Consequências
**Ganhos:** determinístico, grátis, instantâneo, automatizável. O gate não negocia — e é
justamente por não negociar que ele vale.

**Custos e novas restrições:** o script só verifica o que é mecanicamente verificável.
Coerência de sentido fica fora, e é por isso que FR-008 existe. Todo gate novo exige código
e caso de teste.

**O que fica mais difícil depois desta decisão:** gate com critério subjetivo. Não cabe —
se não dá para escrever como condição, não é gate, é revisão.
