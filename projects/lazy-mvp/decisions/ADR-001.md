# ADR-001 — Arquivo como fonte de verdade, sem banco de dados

## Status
Aceita.

## Contexto
A visão original previa banco relacional com documentos Markdown gerados a partir dele, e
deixava aberta a questão da sincronização nos dois sentidos. O consumidor do resultado é
um agente de IA, que lê arquivo. O uso é individual, sem escrita concorrente.

## Decisão
O arquivo Markdown com frontmatter é a única representação do artefato. Não há banco, não
há projeção, não há exportação.

## Alternativas consideradas
| Alternativa | Por que não |
|---|---|
| Banco como fonte, Markdown gerado | Duas representações do mesmo fato divergem na primeira pressa. A sincronização era a parte mais cara de toda a visão |
| Markdown como fonte, banco como índice de consulta | Índice para dezenas de artefatos é custo sem retorno |
| JSON ou YAML puro como artefato | Perde legibilidade humana e renderização no GitHub |

## Consequências
**Ganhos:** uma representação só, que é ao mesmo tempo fonte e entrega. ID estável de
graça (nome do arquivo). Versionamento de graça (git). O PSP deixa de ser exportação e
passa a ser a própria pasta. Caem Flyway, JPA, migração, DTO e docker-compose.

**Custos e novas restrições:** nenhuma consulta relacional. Rastreabilidade resolvida
varrendo a pasta, não com `JOIN`. Escrita concorrente não é suportada.

**O que fica mais difícil depois desta decisão:** adicionar um segundo usuário. Exigiria
reintroduzir banco e revisar ADR-002 junto.
